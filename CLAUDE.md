# AukrofySimulation — CLAUDE.md

## Overview

Go simulation of auction-based resource allocation (module: `github.com/ol1n/auction-sim`). Runs LLM-driven agents (bidders) that bid in Vickrey, Dutch and Penny auctions using role-based personas. Results stored in SQLite, exported as self-contained HTML reports. Has a web interface (htmx + SSE) for live monitoring.

## Build & Run

```bash
# Build both binaries
make build          # → bin/engine, bin/reporter

# Run simulation engine (HTTP server on :8080)
make run            # builds + runs ./bin/engine

# Tests
make test           # go test ./...
make vet            # go vet ./...

# Deployment
make build-linux    # cross-compile for NAS (NAS_ARCH=amd64|arm64)
make docker-build   # build Docker image
make deploy-nas     # rsync + docker compose up on NAS (NAS_HOST, NAS_DIR)

# Clean
make clean          # rm -rf bin/ data/*.db reports/*.html
```

## Project Structure

```
cmd/
  engine/           # HTTP server: API + web UI + simulation orchestration
  reporter/         # CLI: lists persisted simulations (reports are generated by engine)

internal/
  auction/          # Core auction logic (vickrey, dutch, penny, viral mechanisms)
  bidder/           # Agent roles (7), emotions, persona params, LLM decision pool
  config/           # Env-var config loader (.env), NOT YAML
  events/           # In-memory pub/sub bus + SSE
  api/              # HTTP handlers, orchestrator, compare/what-if analysis
  llm/              # LiteLLM client (CF Access), prompt registry, JSON parsing
  reporter/         # Metrics, aggregation, LLM insights, HTML rendering
  store/            # SQLite persistence (modernc.org/sqlite, pure Go)

prompts/            # Runtime LLM prompts: role_*.md (system), decision_*.md (templates)
docs/plans/         # Historical planning documents (not used at runtime)
data/               # SQLite databases (git-ignored)
reports/            # Generated HTML reports (git-ignored)
web/                # templates/ (setup, live view), static/
```

## Key Design

- Configuration is **environment variables only** (`.env`, see `.env.example`) — there is no YAML config
- Bidder pool is defined per-simulation via the web form / `POST /api/v1/simulations` JSON body
- Each auction run: engine ticks → agents decide via LLM (BID/WAIT/LEAVE/BUY_NOW) → clearing → allocation
- LLM: LiteLLM endpoint behind Cloudflare Access; on error/timeout agents fall back to WAIT (without valid `CF_ACCESS_*` creds all agents WAIT → degenerate no-sale results; engine logs a warning at startup)
- Prompts are loaded at startup from `prompts/` (lowercase — case-sensitive on Linux)
- SQLite stores full event log for reproducibility; `GET /healthz` checks DB liveness
- Deployment topology: NAS runs the engine container (see `docs/DEPLOYMENT.md`), DGX Spark serves the LLM endpoint, mac drives builds/deploys via Makefile
